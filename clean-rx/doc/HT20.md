# HT20 interface reference

HT20 frame handling is selected through controller and host build flags.
Station association does not advertise HT capabilities. The separate WMM
station build negotiates non-HT QoS independently of the raw HT20 interface.

The standalone button messenger uses command 12 for direct two-badge MCS0
messages without association or aggregation.

## Build profiles

| Flag | Behavior |
| --- | --- |
| `CLEAN_RX_HT_DATA=1` | Enable versioned command-12 payload handling and HT receive metadata |
| `CLEAN_RX_HT_RX=1` | Select the 3,896-byte extended receive layout |
| `CLEAN_RX_HT_RESPONSE=1` | Enable command-14 QoS/HT response policy; requires extended RX |
| `CLEAN_RX_EDCA=1` | Enable command-15 per-category contention; requires the response build |
| `CLEAN_RX_WMM=1` | Enable non-HT WMM association and command-16 AP policy installation; requires EDCA |

The default value of each flag is zero. Build both endpoints with matching
flags and an explicit controller binary:

```sh
make -C clean-rx/src CC=clang BUILD=../../build/clean-rx-ht \
  PROFILE=diagnostic SELECTION=ht-response
make -C clean-rx/badge BUILD=../../build/clean-rx/badge/ht \
  CONTROLLER_BIN=../../build/clean-rx-ht/cyw43_rx_fw.bin \
  PROFILE=diagnostic SELECTION=ht-response
```

Named selections are owned by [`src/profiles.mk`](../src/profiles.mk).
`PROFILE` selects runtime versus diagnostic behavior; `SELECTION` selects
the feature flags. `ht-data` is the ordinary messenger selection;
`wmm-edca` adds response, EDCA and WMM gates. Both endpoints must use the
same selection. `EXTRA_CFLAGS` supplies additional compiler definitions.

The selected layout is checked through the
[layout manifest](HARDWARE_AND_FIRMWARE.md#memory-layout).

## PHY profile

The frame profile is 20-MHz mixed mode, one spatial stream, BCC, 800-ns
guard interval and MCS0..7. Templates contain six HT-SIG bytes followed
by the MPDU and software FCS.

| MCS | Data bits per symbol | PHYCTL1 |
| --- | --- | --- |
| 0 | 26 | `0x0002` |
| 1 | 52 | `0x0802` |
| 2 | 78 | `0x0a02` |
| 3 | 104 | `0x1002` |
| 4 | 156 | `0x1202` |
| 5 | 208 | `0x1902` |
| 6 | 234 | `0x1a02` |
| 7 | 260 | `0x1c02` |

TX uses `PHYCTL=0x0042`. Separate mixed-mode controls carry legacy RATE
`0xb` and protection LENGTH `3*Nsym+9`, where
`Nsym=ceil((22+8*MPDU_bytes)/Ndbps)`. Airtime is `42+4*Nsym` microseconds.
The controller validates HT-SIG CRC, length, profile and MPDU FCS, and
checks template/control readback.

## Command 12 descriptor

The command is
`12 | clean_tx_length_bits(6 + MPDU_bytes) | (1u << 19)`.
It permits at most one actual transmission; additional flags are rejected.
The staging buffer begins with:

| Offset | Size | Value |
| --- | --- | --- |
| 0 | 1 | Descriptor version |
| 1 | 1 | Profile flags, zero |
| 2 | 1 | MCS, 0..7 |
| 3 | 1 | Reserved, zero |
| 4 | 2 | MPDU length including FCS, little-endian |
| 6 | 2 | Reserved, zero |
| 8 | 6 | HT-SIG matching the descriptor |
| 14 | Variable | MPDU including software FCS |

Versions select these frame shapes:

- **Version 1:** 28..2,332-byte unprotected, non-QoS, unfragmented Data;
  zero Duration, locally administered unicast source and broadcast RA/BSSID.
  The maximum MSDU is 2,304 bytes.
- **Version 2:** the fixed 3,869-byte QoS A-MSDU fixture in the extended
  layout. It uses TID 0, No Ack, nonce-derived addresses and a 3,839-byte
  aggregate containing 2,304-byte and 1,505-byte MSDUs.
- **Version 3:** the fixed 60-byte unprotected QoS normal-ACK fixture,
  using the response build and raw template transmission.
- **Version 4:** the same fixed 60-byte fixture through pinned profile-3
  medium access with automatic PHY turnaround. It requires short slots,
  basic mask `0x150` and response policy 3.

Versions 1..3 require station mode to be disabled and use the raw-transmit
context. Version 4 keeps PSM/RX active. It can return BUSY with zero
attempts before transmitting; inspect the separate ACK result and attempt
count rather than treating command completion as a transmission.
Descriptor construction and validation are defined in
[ht_command.h](../src/diagnostic/ht_command.h).
The runtime profile accepts only version 1; versions 2 and above require
`PROFILE=diagnostic` and their corresponding feature flags.
Disabled build profiles, invalid descriptors and disallowed command bits
produce error `0x85` before transmission. Versions 1..3 do not request
reliable ACK acceptance or RF retries.

## Receive metadata and transport

HT receive packets retain the 18-byte wrapper and MPDU offset:

- Byte 15 contains the validated MCS.
- Byte 16 contains the channel plus `0x80 | 0x40`.
- Byte 17 is profile version 1 for mixed-mode HT20/BCC/800-ns-GI,
  non-A-MPDU frames with validated HT-SIG and terminal PHY format 2.

The `0x40` bit prevents legacy rate interpretation. Descriptor version
and receive-metadata version are separate fields. Complete frames are
assembled from up to two physical F2 fragments, or three in extended RX.
Station profiles 2 and 3 use the eight-slot SRAM capture FIFO to release
PSM SHM before F2 consumption. FIFO publication retains order and the
oldest frame across backpressure; saturation retains the next capture in
SHM. This does not enlarge the single logical F2 credit. Other receive
paths retain a prepared capture while publication is backpressured.

## Command 14 response policy

`14 | (policy << 8)` selects policy 0..3 on a pinned profile-3 radio:
bit 0 permits supported normal-ACK QoS frames, and bit 1 permits supported
HT receptions. Zero disables both. Updates use the deferred policy path
and preserve RX/response ownership.

The final-GoodFCS response hook checks local RA, pinned TA, HT-SIG length
against RXE count, supported three-address QoS Data/Null headers, normal
ACK policy and the selected PHY profile. Per-MCS response records contain
legacy PLCP, PHYCTL1, format and airtime.

Reference response rates for MCS0..7 are 6/12/18/24/36/48/54/54 Mbps.
Selection uses the highest BSS basic rate at or below that reference,
with mandatory OFDM fallback. CCK responses to HT use long preamble.
An accepted incoming ACK is recorded separately from data publication.

## Station peer profiles

### Local target and PHY configuration

The local target is HT20, HT mixed-format, 800-ns GI, BCC and one spatial
stream, MCS0..7. `clean_ht20_capability_ie` serializes an unadvertised
capability record: SM power save disabled, no
HT40/SGI/greenfield/LDPC/STBC/beamforming, 3,839-byte maximum A-MSDU,
8,191-byte A-MPDU target and 16-us minimum MPDU spacing. TX MCS is defined
equal to RX, with maximum RX rate 65 Mbps. The station does not transmit
this element in association requests.

`clean_ht20_select_mcs(mask, ceiling)` selects the highest common MCS
at or below an explicit 0..7 ceiling. Empty/unsupported masks and invalid
ceilings return -1. It is a bounded selection policy, not rate adaptation.
`clean_ht20_configure` instead validates an **exact** MCS request against
an allowed mask, deriving PHY controls, symbols, rate in kbps and airtime.
On rejection it leaves the output untouched; controller callers report an
explicit input error rather than silently reducing the requested MCS.
The actual HT template TX path uses this shared configuration for its
controls and airtime-dependent completion/ACK/drain deadlines.

### Candidate policy and explicit fallback

The badge parses optional HT/WMM elements from validated association
responses separately from beacon discovery. Rejected, misaddressed,
truncated or invalid-FCS responses do not replace the saved response
profile. Missing optional elements are not inherited from an earlier
beacon. Malformed optional elements mark HT fallback while leaving the
legacy association-response result independent.

Beacon refresh detects changes to HT capabilities, operation and all WMM
AC parameters even when legacy rates and slot policy are unchanged.
It preserves the accepted association response and counts subsequent
HT/WMM changes with a saturating counter. Deauthentication or
disassociation clears the saved association profile and counter.

The station's 48-byte peer report starts at badge USB detail offset 1040.
It contains the fallback mask, MCS/channel/capability/protection fields
and four AC records. Byte 19 identifies its source:

| Source | Meaning |
| --- | --- |
| 0 | Beacon discovery; no accepted association profile is retained |
| 1 | Validated association-response profile |
| 2 | Response profile constrained by subsequent HT/WMM beacon changes |

For source 2, MCS is the response/beacon intersection, 40-MHz capability
cannot be added, and operation/protection/WMM fields reflect the latest
beacon. The update counter occupies bytes 44..47, little-endian.

`clean_station_ht_candidate` uses that same constrained profile. Local
TX is limited to the AP's RX MCS mask intersected with MCS0..7; local RX
remains the fixed one-stream target. A valid 40-MHz-capable AP does not
enable local HT40 or SGI. Unknown channel, missing/invalid IEs, unsupported
basic MCS, unusable WMM and unimplemented protection suppress the candidate.
Reserved SM-power-save and A-MPDU-parameter encodings are malformed.

Fallback bits are:

| Bit | Meaning |
| --- | --- |
| 1 | Missing HT capabilities/operation |
| 2 | Malformed or inconsistent peer elements |
| 4 | Invalid or mismatched primary channel |
| 8 | Missing/unsupported MCS or basic-MCS requirements |
| 16 | Unusable WMM/EDCA profile |
| 32 | Live HT station admission is disabled; always set |
| 64 | Required HT protection is unsupported |
| 128 | Local HT-data or extended-RX build is disabled |

Only a profile blocked **solely** by bit 32 has a selectable PHY candidate.
Unavailable candidates have mask 0 / MCS -1. The local target width, GI,
stream count, RX mask and serialized capability record describe the local
configuration, not negotiated HT operation.
Default association requests retain legacy-only advertisement. With
`CLEAN_RX_WMM=1`, a usable beacon WMM Parameter element adds a WMM
Information element to the request, with U-APSD disabled. No HT
Capabilities or HT Operation element is added.

The association response supplies its own WMM parameters. An omitted WMM
element leaves the association non-QoS; malformed, information-only or
unexecutable WMM parameters after an offer produce an explicit host input
error. The host installs accepted parameters using command 16. Subsequent
validated beacon changes update the same combined policy. Withdrawal or
unsupported parameters stop station operation with an explicit
error rather than silently continuing under stale negotiated parameters.

## Command 16 combined WMM station policy

With `CLEAN_RX_WMM=1`, command `16` accepts exactly the following 36-byte
staging layout at `CLEAN_TX_BUFFER_ADDR` for an existing profile-3 station:

| Bytes | Field |
| --- | --- |
| 0..5 | Existing local MAC address |
| 6..11 | Existing pinned peer address |
| 12..13 | BSS basic-rate mask, little-endian |
| 14 | Short-slot flag, 0 or 1 |
| 15 | Station profile, 3 |
| 16 | QoS-only response policy, 1 |
| 17..19 | Reserved, zero |
| 20..35 | Four WMM AC records, in command-15 format |

The command has no flag bits. Addresses, rates, slots, policy and all
records are validated before replacing the pending policy. Basic rates,
slot timing, QoS responses and contention parameters apply together at
the existing idle RX/response boundary. Completion acknowledges queueing,
not RF application. TX defers while a policy is pending.

The station arms QoS-only normal-ACK responses before sending its WMM
association request. Accepted unprotected QoS frames use per-TID
duplicate/fragment state; protected frames bypass that cache until CCMP
authentication. Protected WMM operation sends a TID-0 QoS probe only after
WMM acceptance.
Non-WMM operation uses a non-QoS probe.

The station report at detail offset 768 has six little-endian words:
magic `0x314d4d57`, whether WMM was offered, whether the retained
association negotiated WMM, and the number of queued combined-policy
updates, followed by delivered protected A-MSDUs and their subframe count.
The two aggregate counters occupy detail offsets 784 and 788.
Policy commands keep their mailbox command until commit and fail explicitly
on timeout, cancellation, unexpected replacement or readback mismatch.
Policy commit does not enable HT advertisement or Block ACK responses.
EDCA status is read from detail offset 752; queueing a policy is separate
from its application. The aggregate counters count newly delivered,
fully validated protected aggregates, not retries, individual F2 fragments
or A-MPDUs.

With extended reception and negotiated WMM, the protected receive path
accepts unfragmented QoS A-MSDUs with up to 3,839 aggregate bytes.
Their maximum encrypted MPDU is 3,885 bytes and uses three F2 fragments.
MIC verification, complete aggregate validation and local-destination
checks precede authenticated duplicate processing. See
[protected reception](HARDWARE_AND_FIRMWARE.md#host-mac-and-protected-reception).

The ordinary station path uses the non-A-MPDU RX interface. It does not
install Block ACK agreements or transmit compressed BA responses.
Caller-owned Block ACK/reorder and A-MPDU stream APIs with WPA2 adapters
are separate from station capture and negotiation.
### Finite aggregate diagnostic

Command-12 versions 5..9 are exact diagnostic formats. They require
`PROFILE=diagnostic`, `CLEAN_RX_HT_DATA=1`, `CLEAN_RX_HT_RX=1`, station mode
disabled and one transmission. The controller regenerates the selected
format and rejects mismatched descriptor, body, FCS, command bits or tail
bytes. These versions do not accept arbitrary aggregate payloads.

| Version | Additional gate | Payload |
| --- | --- | --- |
| 5 | `CLEAN_RX_AMPDU_PROBE=1` | Three 80-byte MPDUs in one HT20 aggregate |
| 6 | `CLEAN_RX_HT_STIMULUS=1` | Two 554-byte MPDUs; 1,118-byte PSDU |
| 7 | `CLEAN_RX_HT_HANDOFF_STIMULUS=1` | Two MPDUs of 170/298 or 298/170 bytes; 478-byte PSDU |
| 8 | Version-7 gate plus `CLEAN_RX_HT_HANDOFF_GUARD=1` | Version-7 bodies followed by an 80-byte guard MPDU; 564 physical bytes |
| 9 | `CLEAN_RX_HT_VARIABLE=1` with handoff stimulus | Two-body format selected from eight length pairs |

Version 7 uses nonce byte 10 for the case: good, bad first FCS, bad last
FCS, bad second delimiter CRC, or an eight-byte-overlong second delimiter
claim (0..4). Byte 11 selects body order (1 or 2); byte 12 selects MCS0..7.
Only aggregate index 2 carries the selected invalid bytes. The first
MPDU sets More Data and the second clears it.

The version-7 logical descriptor is 492 bytes, but admission validates all
1,132 staging bytes, including the zero tail. The host must stage the
entire buffer. Version 8 selects the guard-body geometry instead of
version 7. These are unprotected, nonce-bound FromDS QoS frames, not data
under a negotiated Block ACK agreement.

#### Receive and copy controls

The passive observer and finite receive paths have separately gated
controls:

| Flag | Controller behavior |
| --- | --- |
| `CLEAN_RX_HT_COPY_PROBE` | Retain copy-progress and continuation snapshots |
| `CLEAN_RX_HT_COPY_WAIT` | Use a bounded fresh-count wait after EOI; fail on EOF, abort or timeout |
| `CLEAN_RX_HT_COPY_END_PLUS6` | Add six to the diagnostic copy-end value |
| `CLEAN_RX_HT_COPY_QUIET` | Clear and verify the low streaming field before EOI |
| `CLEAN_RX_HT_COPY_DEFER_STREAM` | Select a 384-byte pre-handoff streaming threshold instead of 128 |
| `CLEAN_RX_HT_COPY_DMA_PROBE` | Save selected DMA windows and scan all 32 buffers after DMA shutdown |
| `CLEAN_RX_HT_COPY_STREAM_PHASE` | Select first-body and continuation streaming thresholds |
| `CLEAN_RX_HT_COPY_STREAM_REARM` | Select bounded copy-state/replay actions |
| `CLEAN_RX_HT_COPY_SCOPE` | Select copy/stream state snapshots and epoch-held actions |
| `CLEAN_RX_HT_COPY_SCOPE_NO_REPLAY` | Disable replay in the scope-3/rearm-5 configuration |
| `CLEAN_RX_HT_COPY_SCOPE_REPLAY_FIELD` | Select the replay command field; default `0x83` |
| `CLEAN_RX_HT_NEXT_FIELD` | Select the next-MPDU command field; default `0x83` |
| `CLEAN_RX_HT_ORDERED_FLUSH` | Select proactive (1) or one-shot fault-only (2) ordered RXE/crypto recovery |
| `CLEAN_RX_HT_PREFIX_RECOVERY` | Add count-2/RX-active sampling and a restored PHY-control pulse after a 250-us TSF deadline |
| `CLEAN_RX_HT_EARLY_FIFO` | Publish validated first nonterminal MPDUs through the SRAM/F2 FIFO |

The feature constraints in [ht_observer.h](../src/ht_observer.h) and
[profile_checks.h](../src/profile_checks.h) reject incompatible control
combinations. These controls do not enable HT station advertisement or
general N-body reception.

#### Three-MPDU capture and delivery

`CLEAN_RX_AMPDU_INTERFACE` selects post-completion/body snapshots (1/2)
or early capture (3). Interface 3 uses `CLEAN_RX_AMPDU_HANDOFF=1` for the
prefix-boundary path or `=2` for one-copy continuation. With handoff 2,
the three-bit `CLEAN_RX_AMPDU_BAD_FCS` mask selects per-MPDU FCS faults.
Invalid snapshots do not enter the retained sequence bitmap.

`CLEAN_RX_AMPDU_DMA=1` requires probe/interface-3/handoff-2 and publishes
individual captures through D11 DMA/SRAM/F2. Its header uses tag `0xda16`,
native length 86, outcome 1/2 and ordinal 1..3. Each physical DMA body has
six prefix bytes followed by the complete 80-byte MAC/FCS: the first prefix
equals the retained HT-SIG; continuation prefixes are zero. The post-header
continuation uses copy-command field `0xc3`. Retained-SHM continuation uses
`0x83`.

PHY format 0/1/2 metadata requires exact aggregate HT-SIG matching and
uses diagnostic F2 version 5, not the ordinary nonaggregate HT metadata
version. Format 3 is rejected. Good bodies require complete software FCS
validation; bad outcomes are reclaimed without delivery. Physical prefix
bytes and raw PHY observations are validated/preserved, not fabricated.

`CLEAN_RX_AMPDU_SHM=1` selects retained-SHM delivery instead of DMA
publication. The PSM publishes state 16 as a terminal lease, including
bad-last and all-bad cases. The controller pauses and verifies the PSM,
copies the committed three-slot record, validates each body and outcome,
and publishes through the eight-slot SRAM/F2 FIFO. This record is consumed
once per boot.

The badge stores delivered 80-byte payloads at USB detail offsets
`1664 + 80 * sequence`. Publication/claim/release timestamps use the PSM
TSF domain; they are not physical EOF-to-air measurements. Neither
delivery mode installs a general Block ACK agreement.

### Opt-in diagnostic compressed BA

`CLEAN_RX_AMPDU_BA=1` requires the retained-SHM profile and defaults to zero.
Command `17 | (mcs << 8)` arms one unused pinned three-by-80-byte capture
at MCS0..7, station hardware profile 3 and basic mask `0x150`.
The PSM permit is written last after pause/readback-verified response
parameter installation. Disabled or invalid commands fail explicitly.

The PSM constructs a compressed BA from retained good-FCS, matching
headers, waits for terminal status and uses the hardware SIFS TX-control
path. This command does not install a general BA agreement or enable HT
association.

## Command 15 contention parameters

With `CLEAN_RX_EDCA=1`, command `15` queues four WMM-format AC parameter
records staged as 16 bytes at `CLEAN_TX_BUFFER_ADDR`. It accepts no command
flags and requires pinned station profile 3. Each four-byte record contains:

| Byte | Field |
| --- | --- |
| 0 | AIFSN in bits 3..0, ACM in bit 4, ACI in bits 6..5, bit 7 zero |
| 1 | ECWmin in bits 3..0, ECWmax in bits 7..4 |
| 2..3 | TXOP limit in 32-microsecond units, little-endian |

ACI values 0..3 mean BE, BK, VI and VO. Supply each exactly once in any
order. AIFSN must be 2..15 and ECWmin <= ECWmax <= 10. Invalid parameters,
disabled builds and other profiles produce error `0x85`. Completion
acknowledges queueing, not application; wait for `policy_pending` to clear.
Parameters apply at an idle RX/response boundary and preserve NAV/EIFS.

This interface serializes one outstanding frame, with TID 0..7.
The TID mapping is BE/BK/BK/BE/VI/VI/VO/VO. ACM categories without admission
are skipped in VO-to-VI-to-BE-to-BK order; transmission is rejected if no
category is available. Each category retains its own contention window,
random state and residual slots. AIFS is `10 + AIFSN * slot_us`.
Retry growth saturates at that category's CWmax. A positive TXOP limit
bounds the single data/SIFS/ACK exchange; zero allows one exchange.
The interface does not batch frames into a TXOP.

EDCA accepts the version-4 HT fixture and reliable legacy-PHY management,
non-QoS ToDS data, and three-address QoS ToDS Data/Null frames. Management
uses the VO selection, non-QoS data uses BE, and QoS uses its TID.
QoS TX requires normal ACK policy, TID 0..7, zero second QoS-control byte,
no A-MSDU, no HT Control, no fragmentation and at most 2,304 MSDU bytes
(plus the 16-byte CCMP envelope for protected Data). Protected QoS Data preserves
its ciphertext and PN across retries. TXOP checks use actual legacy
rate/preamble/length or the fixed HT fixture's airtime.

EDCA remains active until reset or station reconfiguration. Station
capability advertisement is independent of command 15.

Read the 16-byte `clean_edca_status_t` at `CLEAN_EDCA_STATUS_ADDR` (`0x204a0`):

| Offset | Size | Field |
| --- | --- | --- |
| 0 | 4 | Magic `0x31434445` |
| 4, 6 | 2 each | Selected CWmin and CWmax |
| 8 | 2 | Programmed PSM AIFS in microseconds |
| 10 | 2 | Selected TXOP in 32-microsecond units |
| 12, 13, 14, 15 | 1 each | Selected AC, requested TID, enabled, reserved zero |

The record is a policy snapshot, not an RF timing measurement or ACK result.

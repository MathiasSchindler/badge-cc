# R06 aggregate DMA repair, 2026-10-24

## Scope and outcome

This record closes the bounded R06 decoder/continuation defect, not general
HT, A-MPDU, Block ACK or loss-free reception qualification.
The [work item](todo.md) followed the separate DMA failures in the
[R03 campaign](HARDWARE_REGRESSION_R03_2026-10-24.md).

The user authorized up to 32 paired trials on Badge A
`08DA26F86E57F5EA` and Badge B `9BBF88DD17D66E7D`, with complete verified
backups/restoration. The campaign used **31 trials and 31 fresh challenges**.
The Pico was not accessed. All trials used channel 6 and the existing
[bounded orchestration](../guides/HOST_TOOLS.md#bounded-usb-orchestration).

The repaired DMA path delivered all three exact bodies in both directions at
MCS0/3/7. Bad-middle and all-bad controls passed 4/4 each. Empty captures
remain: one SHM control and one final-image DMA cell initially failed, and
each passed its single fresh repeat. These failures are retained, not
converted into first-attempt success.

Evidence is under `build/radio-regression-r06-20261024/`.

## Causal sequence

### The original 0x8d is a decoder rejection, not proven ring corruption

The saved R03 failing buffers have length 86, good outcome 1, ordinal 1,
tag `0xda15`, valid aggregate HT-SIG and complete good MAC/FCS, but PHY format
0. The old decoder required format 1 or 2 and mapped that rejection to
`0x8d`. The fault address/value alone did not identify a descriptor failure.

A native regression fails on that format-zero admission before the repair.
The decoder and diagnostic version-5 metadata now admit format 0/1/2 only
with the exact aggregate HT-SIG and fixed body contract. Format 3 remains
invalid. Complete software FCS, length, ordinal, header-tag and prefix
checks remain mandatory for delivery. Ordinary nonaggregate HT admission
and non-delivery profiles retain their previous behavior.

The first instrumented PHY-only build had no controller faults in four
MCS0/7 trials, but every trial still delivered only sequences 0/1. Thus
changing PHY admission did **not** repair the missing third body.

### DMA needs the next-MPDU command after header publication

The DMA continuation used body-start field `0x83` after publishing each
header. The existing
[next-MPDU experiment](ht20/NEXT_MPDU_AND_VARIABLE_LENGTH.md#one-byte-next-mpdu-discriminator)
identified field `0xc3` for the corresponding streaming transition.
The change here is DMA-only; retained-SHM continuation stays at `0x83`.

The first `0xc3` trial retained all three exact fresh bodies. It then failed
with `0x8e` because the old DMA decoder still expected continuation MAC
bytes at buffer offset 38. The frozen buffer proves the distinction:

- Header: length 80, good outcome, ordinal 2, PHY format 0.
- Six zero staging bytes at offsets 38..43.
- The exact fresh sequence-one MAC/FCS at offsets 44..123.
- Software FCS fails at offset 38 and passes at offset 44.

This is not permission to ignore corrupt MAC bytes. The repair describes
and validates the physical layout: native length 86 for every ordinal,
header tag `0xda16`, physical PLCP prefix for ordinal one, and six zero
prefix bytes for subsequent ordinals. Only the actual complete 80 DMA MAC
bytes are delivered. The retained HT-SIG normalizes the existing F2 envelope;
no MAC bytes are synthesized or substituted from SHM.

The old `0xda15` layout is explicitly rejected. Neither crypto-reset
bypass, arbitrary delay, extra DMA drain, fabricated completion nor relaxed
three-body acceptance was used. DMA ring reclamation is unchanged.

### Preserve ownership and completion evidence

The controller saves the first failing descriptor and physical 128-byte
buffer prefix before reclaim/reset. It also samples consumer/producer,
DMA status 0/1, PSM pending/submitted state, RXE status/count, PHY and copy
control. A healthy run saves the next-consumer state before shutdown;
it does not claim that an unused zero buffer is a missing completed frame.

The final record is 180 bytes at SRAM `0x20b00`, committed with magic last
and bound to the controller generation. Shutdown cannot overwrite the first
fault record. The badge reads that frozen record instead of rereading a
potentially reused live DMA buffer. Context/prefix/generation use existing
reserved report space; the 2,092-byte report and delivered-body offsets
are unchanged. The collector reports missing/stale state as `null`.
See the [state format](../guides/HOST_TOOLS.md#aggregate-dma-state).

The intermediate fault experiment predates the record's added generation
word. Its complete R03-format endpoint snapshot still binds the request
and controller generation; it is not presented as the final record format.

All rows retain every attempt, including the five deliberate intermediate
failures used to isolate the mechanism.

The first six passing repaired trials and the final image have identical
controller bytes. The badge changed only its two build-ID words after
source/test updates; the complete six-cell final-image check and its one
repeat nevertheless used the exact final image and collector.

The two empty captures had completed, valid endpoint snapshots and no
controller fault. The DMA empty capture submitted no aggregate DMA bodies.
They remain reception evidence for R07; their cause is not established by
this campaign. A passing fresh repeat is not loss-free qualification.

The SHM PSM instruction bytes compare exactly with R05. No BA experiment
was enabled in these DMA controls. Physical absence/timing of BA and general
Immediate BA operation are not qualified here.

The intermediate `0x8e` receiver exited with failure and R04 stopped its
partner. That transmitter has no raw snapshot; its empty JSON/stderr and
runner logs are retained. It is never accepted as a paired result.

## Independent audit and native validation

`harness/r06-audit.cjs` reruns the unchanged strict pair oracle against
actual raw/JSON evidence, not stored success flags. It also checks:

- 31 distinct challenges and the authorized trial limit.
- All planned directions/rates, exact bad/good payloads/FCS, delivery
  bitmaps/counts/duplicates and applicable terminal leases.
- Endpoint serials and readiness-reported image IDs.
- Full raw nonce/controller-generation binding and complete snapshot bits.
- DMA context words, descriptor buffer/index relationships, physical prefix
  bytes and generation binding.
- All 36 RF-phase image/collector/source-diff hashes.
- Exact final image/controller/collector identity and complete restoration.

The strict oracle's acceptance functions are byte-identical to the R05
oracle; only native/self-test coverage was extended. There are **24 accepted
pairs, seven retained failed attempts, 61 complete endpoint snapshots and
one explicitly cancelled/missing transmitter snapshot**. All 18 distinct
repaired-DMA/control cells have a strict passing attempt.

ASan/UBSan controller and badge suites pass for default, DMA, bad-middle,
all-bad and SHM builds. Coverage includes the actual frozen continuation,
all PHY formats, exact prefix/layout/tag/length checks, every MPDU bit and
HT-SIG mutation, truncation, atomic rejection, good/bad PSM continuation,
EOF/count/wrap behavior and valid/stale collector state.
Standalone-header, ABI, source-containment and composition guards pass.
The old frozen-body guards exempt only the reviewed R06 codecs/runtime
changes; every other PSM tuple and resolved hook target remains compared.
No packages, JavaScript framework, CI, libc or external firmware dependency
was added.
